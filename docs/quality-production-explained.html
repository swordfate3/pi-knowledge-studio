资料找到了，
为什么还是答不出来？

Studio 不只有一个模型。它更像一个小图书馆：找资料、看图片、写答案、保管资料，是不同的工作。

先说结论：已知问题不能归因于远程 embedding1。最典型的失败评测，根本没有调用远程向量服务。
本页是解释与教学示意，没有进行新的远程检查或推理。

① 三个“工作人员”，不要混为一谈

🔎

找资料的

Embedding（向量模型）
把意思变成数字，帮助找到意思相近的文字。

像图书馆的找书助手。
不负责最后写答案。

✍️

组织答案的

生成模型：本次是 Qwen
读取找到的证据，判断能不能答、要不要配图。

像拿到参考书的答题人。
拿到书，也可能判断错。

👁️

看图片的

视觉模型：本次测了 SmolVLM
接收图片像素，描述里面有什么。

像看图助手。
不等于找书或写答案的模型。

还有两个容易混淆的名字

Reranker（重排序）：把已经找到的候选资料重新排队，让更相关的排前面。

OCR（图片转文字）：从扫描页识别文字。识别稿仍标记“未核实”，不能自动当作准确原文。

② 单步看：A25 到底在哪一步失败？

这道题同时要求文字说明和文档中的指定原图。下面只演示已经观察到的处理过程。

这次走的是关键词检索。没有调用 embedding，也没有把图片像素交给生成模型；它看到的是文字、图片标识和关联信息。

为什么说不是 embedding1 引起的这次失败？

评测脚本调用 runtime.search(question, 10)，没有传入向量模型。检索代码仅在传入 provider 时才执行向量查询。

更直接的证据是：指定原图及其关联文字已经进入该题的证据包和生成上下文。不是“图片掉在路上”。

这只定位了 A25。它既不能证明远程 embedding 在所有问题上都好，也不能证明其他题目不会发生检索遗漏。

③ 真正的问题：把“能答”错判成“不能答”

正常的保护

书里确实没有 → 不乱编

模型说“证据不足”。
这叫正确弃答，是好事。

A25 的问题

所需资料已有 → 仍不回答

模型把配图要求判为缺少支持。
按冻结题目标准，这是错误弃答。

不能为了“看起来成功”，强行塞一张图或放松检查。这样可能从“不敢答”变成“乱答”。

已经知道什么？还不知道什么？

已证实：证据到了；模型将配图要求标记为缺失；此次响应完成，没有超时；系统据此返回无文档的弃答结果。

尚未证实：模型为什么这样判断。可能把“找到原图”与“确认图里画什么”混淆，但这只是待验证的解释，不能说已经找到根因。

生成模型这次没看像素。图片的文件身份正确，不等于图片内容、适用性已被视觉验证。原图空标题等上下文因素也不能直接当作已证实原因。

大意：一个长方形和一个蓝色球体。

漏掉红色与位置；没有精确识别方块；把平面圆说成球体。

方块数学上也属于矩形，但本次要求精确识别具体形状。这个失败来自测试的视觉模型，不是 embedding 的向量计算；也不能推广成所有视觉模型都不行。

离线校验器解决了什么，没解决什么？

它像查账员：检查文件、历史记录、原图与 OCR 的关系是否一致，不改库。

检查预算用完，或向量元信息不足以认证时，诚实返回“未完成”。

它不是备份，不会自动清垃圾，也不能恢复一份已经丢失的原文件。
