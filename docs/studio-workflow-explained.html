它就是一个“会帮你找书的图书管理员”。
你给它资料，它保存资料；你提问题，它告诉你答案来自哪一页。

Studio 管理员

先记住：有两扇门

小资料 / 笔记

普通知识库

像一个文件夹。你给它一个名字，例如：

freertos-notes

以后用“知识库名称”查看它。

可以查看：

/studio list freertos-notes
整本 RTOS PDF

PDF 书籍库

像一整本带书号的书。它不会叫 collection。

系统会自动给它一个很长的书号：

book_……

以后用“书号”查看和搜索它。

你的 RTOS 书：只看这条路线

1️⃣交给 Studio

告诉它 PDF 在哪里

→
2️⃣Studio 读书

按页保存文字和图片

→
3️⃣得到书号

book_……

→
4️⃣变成可搜索

书读完、索引完成

→
5️⃣提问题

返回页码和原文

实际使用时，你只需要说这句话

把这本 RTOS PDF 建成可搜索的书籍库： documents/books/FreeRTOS内核实现与应用开发实战指南：基于STM32 (刘火良, 杨森) (Z-Library).pdf

我来负责后面的步骤。你只需要在需要时确认“允许读取这本书”。

之后怎么查？

先看读到哪了

/studio books book_……

“book_……”替换成刚才得到的书号。

再问书里的内容

/studio book-search book_…… "任务切换怎么实现？"

结果会带上书中的物理页码。

为什么刚才 list 查不到？

因为你查的是“文件夹式知识库”，但 RTOS PDF 属于“整本书式知识库”。

不是书没了，也不是 Studio 坏了，只是查错了门。

电脑里的 4 个抽屉

🗂️

collections

普通资料库。

放笔记、Markdown、TXT 等小资料。

现在：空的。

📦

exports

打包结果。

把搜索到的内容导出成可带走的文档包。

现在：空的。

📖

pdf-jobs

读书过程。

PDF 正在被读取时，临时放在这里。

读完后，这里可能没有东西。

🔎

pdf-generations

PDF 的搜索目录。

书里的文字、页码和搜索索引放在这里。

当前 RTOS 书的数据就在这里。

一句话记忆

collections 放普通资料；pdf-generations 放 RTOS 书的搜索目录；exports 放导出结果；pdf-jobs 放读书过程。
