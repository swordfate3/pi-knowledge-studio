# Offline synthetic retrieval evaluation

## Run and scope

From the project root, with the project's existing Node/TypeScript setup:

```sh
node --experimental-strip-types --test tests/retrieval-quality.test.ts
```

The existing `npm test` glob also includes this test. No dependencies, runtime scoring changes, real models, network calls, or private documents are involved. It exercises `KnowledgeRuntime.ingest`, `search(query, 5)`, and `index(fakeEmbedding)` against real temporary SQLite catalogs and blob stores. Only vision-hint insertion uses `SqliteCatalog` directly. Temporary source/data directories are removed in `finally`, including on assertion failure.

This is a **closed-world synthetic regression baseline**, not held-out retrieval quality evidence. Gold labels are explicitly authored before retrieval, never inferred from returned rankings. Each lexical query has one distinct relevant document; related API documents are deliberately non-gold for that exact fixture intent. This does not imply those documents are irrelevant to a real user's broader question.

All seven PNGs are deterministic 12×8 RGB schematic diagrams: white background, two colored blocks connected by a horizontal line. At zero-based coordinates, colored pixels satisfy `(2 <= y <= 5 && (x <= 3 || x >= 8)) || (y == 3 && 3 < x < 8)`. Their RGB is `(20 + 12*i, 70, 150)` for zero-based corpus row `i`; other pixels are `(255,255,255)`. They are encoded with the existing `encodePng`, linked by Markdown, not generated by a model. The test asserts seven distinct blob hashes. These tiny fixtures test association/provenance, not diagram understanding.

Short Chinese queries include single-character `堆` and `流`, two-character `任务`, `队列`, and `互斥`. Shared wording and API prefixes create distractors. Every Latin-starting query must return **only** its gold document, additionally checking full-identifier discrimination (`xQueueCreate` versus `xQueueCreateStatic`, and static/ISR suffixes) rather than accepting prefix matches merely because gold appears somewhere in the top five.

## Metrics and reproducibility

- Document Recall@5 = `|gold document IDs ∩ first five hit document IDs| / |gold document IDs|`. Gold is a singleton and each document has one element, so each query scores 0 or 1; this equals hit rate here. Lexical aggregate is the macro average across 16 queries.
- Image Recall@5 = `|gold image occurrences ∩ first five bundle image occurrences| / |gold image occurrences|`. Occurrences are matched by original source ID **and** PNG blob hash, not caption or model description. The image aggregate averages only the seven queries with image gold; the other nine report `null`, not zero. This measures runtime linked-image delivery, not an independent image ranking algorithm.
- All baseline queries use runtime lexical search without embedding, reranker, or hints. Each is repeated through a reopened runtime over the same catalog, with identical hit-ID order and image evidence asserted.
- The complete evaluation runs twice with independent fresh temp roots/catalogs. It compares per-query recalls and aggregate results, not random bundle IDs, path-derived source IDs, or cross-root tie ordering.
- Regression thresholds are exactly **1.0** for lexical macro Recall@5 and image macro Recall@5, with per-query assertions too. They lock down this deliberately easy observed baseline, not a claimed deployment SLA. No production scoring is fitted to these examples.
- TAP diagnostics print per-query gold, recall and image recall plus aggregates. Any assertion failure fails the test rather than silently dropping the query.

## Separate synthetic discovery controls

### Deterministic fake embeddings (not real semantic quality)

`fakeEmbedding` is an explicit 16-dimensional one-hot lookup. Document vectors are selected by exact fixture text. The only accepted query inputs map as follows:

| Query (absent from lexical corpus) | Gold | Image gold |
| --- | --- | --- |
| dispatchparcel | queue | queue.png |
| exclusiveownership | mutex | mutex.png |
| expirycallback | timer | timer.png |

For each query, lexical-only runtime search must reject with `No relevant evidence found`. Runtime indexing followed by search with `fakeEmbedding` must return the gold as its only hit, with no lexical rank and dense rank 1, and its original linked PNG. The runtime API is hybrid; these are **dense-only candidates because lexical retrieval has no matches**, not a separate semantic-only search API. This oracle-like mapping proves candidate plumbing and image association only. It cannot establish paraphrase generalization or embedding quality.

### Vision-hint-only discovery and original authority

After the lexical and embedding evaluations, the test inserts a validated hint bound to the `isr` source revision/hash and original image ID/hash. The exact description is `violetbridge fabricated synthetic diagram description`; model/prompt fingerprints are SHA-256 of `offline-fixture-model` and `offline-fixture-prompt`. No vision model is invoked.

Lexical search for `violetbridge` must fail before insertion. After insertion, search without embeddings must retrieve only `isr`, return unchanged original element text and image hash/origin kind, and preserve original PNG bytes. The description must not appear in the serialized search result. This is a discovery/authority control, not vision accuracy evidence or a comprehensive prompt-injection test.

## Measured baseline

Observed with the command above, including both fresh-catalog runs:

| Track | Queries | Document Recall@5 | Image Recall@5 |
| --- | ---: | ---: | ---: |
| Runtime lexical baseline | 16 | 16/16 = **1.000** | 7/7 = **1.000** |
| Fake-embedding dense-only control | 3 | 3/3 = **1.000** | 3/3 = **1.000** |
| Synthetic hint-only control | 1 | 1/1 = **1.000** | 1/1 = **1.000** |

All 16 lexical rows scored document recall 1; all seven image-gold rows scored image recall 1. Reopened-runtime checks, fresh-catalog metric equality, exact-identifier checks and hint authority checks passed. The test emits the measured values, so future runs can detect baseline drift rather than relying on this recorded table.

## Live embedding smoke test (separate from automated suite)

The existing WeMM service was additionally exercised using six **newly authored synthetic** Chinese documents and paraphrase queries. These are not private source documents or a held-out benchmark. Each document linked a 1×1 PNG; all PNGs had identical bytes, so image delivery was checked by source identity as well as blob hash. Temporary catalogs and sources were removed after the run.

| Gold | Exact synthetic text | Query | Lexical gold rank | Hybrid gold rank |
| --- | --- | --- | ---: | ---: |
| queue | 队列在任务之间按顺序传递消息并复制消息内容。 | 两个执行单元怎样交换消息？ | 3 | 1 |
| mutex | 互斥锁保护共享资源，避免两个任务同时修改同一数据。 | 怎么防止并发修改同一资源？ | 1 | 1 |
| timer | 软件定时器到期时执行回调函数，可周期性触发。 | 如何定期调用一个处理函数？ | 1 | 1 |
| heap | 动态堆内存分配返回可用内存地址，使用后应释放。 | 运行时申请的内存用完应该怎样处理？ | 1 | 1 |
| notify | 任务通知可以直接唤醒指定任务，不需要中间消息容器。 | 怎样直接唤醒等待中的指定任务？ | 1 | 1 |
| isr | 中断服务程序应使用专用的 FromISR 接口，避免调用阻塞函数。 | 硬件中断里应选用什么接口？ | 1 | 1 |

Model: `tencent/WeMM-Embedding-4B`, revision `a28b25c5d18cf71ec46b115e06ea79ab00ee4819`, 512 dimensions, empty query/document prefixes. Seven embedding requests: one six-document batch and six queries. Hybrid top-1 = 6/6 versus lexical 5/6; hybrid document Recall@5 and source-linked image delivery = 6/6. Per-query elapsed time including hybrid and lexical reads was 430–448 ms in this one run, not a latency SLA. No reranker, vision hints or visual understanding was involved. This demonstrates real embedding/runtime plumbing; it does not establish statistically meaningful superiority or quality on actual user documents.

## Limits / pending real held-out evaluation

The corpus is tiny, short, hand-authored, and dominated by exact terms. Single-label gold omits graded relevance and multiple valid answers. There is no production-scale distractor set, long/multi-element document test, OCR, PDF/DOCX evaluation, duplicate-source evaluation, real visual interpretation, real embedding/reranker comparison, generation quality, latency budget, precision/MRR/nDCG assessment, or adversarial security claim here. Perfect synthetic Recall@5 is not evidence of real-world retrieval quality.

**A larger real held-out evaluation is still pending.** It needs separately curated Chinese/identifier/paraphrase queries, independently adjudicated multi-document and image-occurrence gold, realistic distractors/formats, a frozen test split separate from tuning, and explicit consent/configuration for any model use. Report lexical/dense/hybrid/reranked ablations, image provenance and precision/ranking metrics alongside recall. Do not tune production scores against this regression fixture and then advertise it as held-out validation.
